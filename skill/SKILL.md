# scansci-svg · 科研绘图、编辑与格式转换

**推荐模型：GPT-6 Astra。** 沿用用户选定的模型与设置；具体效果按任务验收和同条件对照记录。

将照片、文本和生成式视觉参考转化为科学含义准确、视觉表达清晰、可持续编辑的 SVG。分别验收科学内容、版面可读性和编辑行为。

文字创作直接构形；参考图按还原目标与后续编辑需求选择重建、描摹或局部混合。将科学约束融入绘制，复用已有素材、转换与编辑工具。

绘图主线是忠实重建、精细临摹、部件修改、成套一致性、论文组图与可编辑 PPT；SVG 原理、排错和跨格式选择通过按需知识库支持。价值按具体任务中的还原质量、修改范围、重复修改工作量及交付可用性判断。动画、实体制作和三维处理随用户需求启用。

文字直接说明动作、依据和结果。检查记录写实际完成项；影响当前图件的不确定性写清具体对象、缺项及处理方式。

## 先判断用户要完成的操作

用户要求画图、修改、组图、转换、修复或生成回放时，完成对应操作并交付所需文件。结合上下文理解“帮我转成……”“这段字改一下”“导入后错位了”等说法；信息充分就执行。用户只问原理、比较或明确说先不制作时，直接解释。

按真实输入选路：有原始数据与作图代码时从源导出；已有 SVG、矢量 PDF 或设计文件时复用其对象；只有位图时再选择描摹或重建。先检查文件内容、当前版本与用户要修改的部件，沿用已确认的科学内容和编辑要求。

转换任务从 [实际执行与恢复](references/svg-handbook.md#choose) 进入；只加载当前方向或症状对应的条目，复用可用工具。首选工具缺失时继续寻找满足同一输出与编辑要求的替代；确定的缺字、错位或对象遗漏先修复，再验证目标产物。完成以用户能拿到并使用所需文件为准。

下文原生矢量约定用于默认静态科研图。明确的 PNG-only、照片标注、网页交互或数据图像面板请求按对应用途交付；指定格式优先于默认 SVG＋预览。知识库为执行提供依据，SVG 原理与路线比较也可单独查询。

## 指令不明确时先追问

- 先结合当前指令、附件和已确认的上下文判断目标。存在会明显改变结果的多种合理解释时，在相关制作前追问；重点澄清对象与范围、忠实还原或重新设计、科学阶段/关系、组图或变体的区别，以及交付格式与编辑粒度。
- 每轮集中问 1–3 个关键问题，用具体选项说明不同结果，并给出简短推荐；用户可以自由补充。问题直接指出缺少的决定，例如“这张图希望完整还原，还是只提取植物？”、“这套变体要比较生长阶段，还是同一对象的配色？”。
- 参考图的编辑用途会改变制作路线时，优先问“生成后主要希望修改哪些内容？”，据此确定需要单独处理的部件、文字和连接。已有明确编辑要求时直接沿用。
- 等用户回答后再执行依赖该选择的部分；期间可读取源文件、盘点已有素材或核实共同需要的事实。回答到达后将其融入任务要求，直接继续执行。推荐项只有在用户选择或明确委托按推荐执行后才作为决定。
- 已明确或已确认的要求直接沿用。含义清楚的“转为 SVG”先按实际源类型选择导出或转换，位图参考采用忠实重建或相应描摹；已委托自行设计的风格及普通技术细节按合理默认执行。可由原文件或可靠资料核实的事实先查证，将用户偏好与事实缺项分开处理。
- “继续”沿用尚未完成的已确认任务或明确的下一步；当前任务已完成、后续方向有多个时，先问要推进哪一项。“优化”“不好看”等反馈若无法从上下文定位目标，先澄清要改的图件、部位或效果。

## 普通单图的默认执行

- **范围随请求**：先完成用户点名的对象和结构。剖面、局部放大、机制面板及更多分子细节，仅在用户要求或确实需要它们才能表达本题时增加；不因查到更多资料扩大图件。
- **证据够用即绘制**：优先复用当前任务或项目已有、可追溯且条件匹配的资料，只补查影响构形的缺项。关键特征已有支持即停止检索；来源失败的替代与停止条件见 [对象特征与结构核实](references/morphology-evidence.md#何时查查到哪里停)。
- **交付保持精简**：默认一份 SVG 加一张实际预览，附几句必要的来源与简化说明。无标注版、多种尺寸、额外格式、检查拼图、JSON 和长报告仅按需生成；可直接写 SVG 时不另搭生成器。
- **检查随风险**：普通图由绘制者集中核对关键科学关系、实际渲染和编辑分组；发现问题后修正并复查受影响部分。共享引用、复杂联动、目标编辑器兼容或用户明确要求时使用专项检查；独立审查按实际风险与项目要求启动。

首次在 Zcode 等新宿主使用、看图工具不确定，或实际绘图失稳时，读 [跨模型执行卡](references/cross-model.md)。普通已验证任务无需额外加载。用户要求模型对比或维护能力记录时，再读 [轻量回归评测](references/evaluation.md)。

## 植物分类学黑白线稿模式

用户明确要求“植物墨线图”时，使用 [植物墨线图：先生图后重建](references/botanical-ink-reconstruction.md)。该模式优先用生成参考确定精细笔法与构图，再重建原生 SVG；交付和投稿名称保留“墨线图”。已给定满意的参考图时直接进入重建，用户指定直接构形或仅转格式时按指定路线执行。

用户画植物时明确提出“黑白线稿”“植物志风格”“分类学插图”“墨线图”或 taxonomic botanical line drawing，启用 [植物分类学黑白线稿](references/botanical-line-art.md)。普通植物科研示意仍沿用默认风格；仅要求去色时先保留原图内容和构图，不自动扩成分类学图版。

该模式以可核实的鉴别特征为中心，用纯黑轮廓、结构线和必要的点描/排线表达全株姿态及用户所需的叶、花、果、种子或解剖局部。植物志描述、标本/实拍与分类学文献分别约束形态、个体姿态和诊断细节；未获支持的隐藏结构、根型、器官数量和尺度不补画。图版范围、比例尺、分图字母与标注依用途确定，SVG 按全株、局部、剖面、纹理和标注保留可编辑分组。

该模式有本地 [植物墨线参考板与原图索引](references/botanical-ink-reference.md)：绘制前实际查看总览，按本图所需笔法放大相关原图；风格参考与目标物种的形态证据共同使用。

## 组图与成套制作

连续制作时保留已验收的基准 SVG：从它制作指定变体，再组合面板，返修直接修改交付源文件。沿用部件身份、来源和配色含义；只加载当前操作需要的参考。单次交付按用户请求，不自动展开整个流程。

已有素材的重复拼版复用 `compose_svg.py`；从素材库组建场景时，用 `compose_scene.py --find "关键词"` 检索已标注部件，查看候选图后再选择。按 ID 改色、移动和修改简单标签可用 `edit_svg.py`。脚本用法见 [科研组图](references/figure-composition.md) 与 [文字与部件编辑](references/editable-workflow.md#按部件执行修改)。需要新形态时再直接构形。

带跨对象连线的场景，在配方中绑定两端的对象与部件点。位置或尺寸修改写回配方后重新生成，连接端点与关系标签随之更新；检查连接路径的遮挡、方向与含义。交付时保留配方与底图，供后续返修。

- 用户要求拼成整图、多面板对比、机制图或图形摘要时，读 [科研组图](references/figure-composition.md)。先确定整图表达与关系，再复用匹配素材、协调样式并组织面板、对象和连接；已有 SVG 的重复拼版可用配套脚本。
- 用户要求同一对象的阶段、状态、视角或展示变体时，读 [成套变体](references/variation-and-learning.md#成套变体)。确定共同特征与每版变化，保留对应部件身份，逐版验证变化并统一整套风格；默认交付各版 SVG 与一张总览预览。
- “不同阶段排成一张图”等请求组合两种模式：先得到科学内容匹配的变体，再按比较目的组图。复用本套已核对的资料和结构，缺项按变化范围补查。

## 三类输入，共用科学表达核心

| 输入 | 保留与转化 | 证据边界 |
| --- | --- | --- |
| 照片 | 任务相关的个体形态、比例、可见结构、空间关系；依据用途去除环境或简化纹理 | 隐藏结构保留未定；连接依可见接合或结构资料确认，精确尺度依标定数据确定 |
| 文本 | 对象、数量、条件、空间、连接和方向转成图形；没有指定的视觉风格可自行设计 | 不擅自增加因果、物种特征、接口或实验步骤；影响科学含义的缺项才核实或询问 |
| 生成图/插画（包括 image2） | 提取构图、姿态和风格，重建可编辑路径；有依据时修正原图错误 | 用任务描述和独立资料核对科学内容，简述实质改动与未确认项 |

直接使用已有参考图；用户要求生成参考，或采用植物墨线图的先生图后重建路线时，调用对应图像工具。记录实际来源、授权和生成/补绘过程，标明照片、生成参考或转绘插画。昆虫专项任务读 [昆虫实拍参考](references/insect-photo.md)，可使用成虫数据库筛选。鸟类专项任务再读 [鸟类照片规则](references/bird-photo.md)，需要局部画法时查 [参考示例](references/bird-examples.md)。

### 参考图的路线选择

| 交付重点 | 优先尝试 | 需要完成的整理 |
| --- | --- | --- |
| 保留已有插画的复杂轮廓、斑纹与细节 | 用可用的 VTracer 等工具描摹整图或必要区域 | 对照检查细节、色带与残边；按用途组织部件 |
| 修改文字、箭头、流程关系 | 重建文字与连接；复杂图形按需描摹 | 清除旧字轮廓，保持方向、端点归属与标签对应 |
| 单独修改花朵、翅膀等部件 | 确定完整部件边界，再分离描摹或局部构形 | 检查跨区路径、叠放与遮挡后的底层内容 |
| 从文字创作、改变姿态或结构 | 直接构形，复用匹配的已有部件 | 核对新形态与连接，保留无关的正确区域 |

同一图按区域选择，沿用用户的精细度与完整编辑要求。局部描摹样本用于相近插画的候选路线；总耗时包括区域判断、文字恢复、整理与返修。VTracer 的可选入口为 `scripts/trace_svg.py`，依赖、用法及整理方法见 [描摹与部件整理](references/editable-workflow.md#描摹与部件整理)。

已有 SVG 优先在源文件中局部修改；保留已验收的路径、对象 ID 与中间结果。只有发生变化或已确认失真的区域需要重做。调用外部服务须符合当前任务授权；普通本地描摹使用当前文件与可用工具。

用户要求“把这张图转为 SVG”“按原图还原”时，采用 [参考图忠实重建](references/editable-workflow.md#参考图忠实重建)。要求精细临摹、插画复现或保留质感时，按 [保真与细节选择](references/editable-workflow.md#保真与细节选择) 加强局部轮廓、线条、纹理与明暗还原；同一图可混合使用语义重建和局部临摹。用户仅参考风格、提取对象或要求重新设计时沿用对应范围。

位图示意图按“整图含义 → 对象及关系 → 部件与叠放 → 几何与样式”重建。简单对象直接构形，必要的复杂局部轮廓才按需描摹；具体处理见 [转绘洁净度](references/editable-workflow.md#转绘洁净度)，计时包含构形、整理与交付。

## 科学内容怎样进入绘制

鸟类、昆虫和植物的新绘、形态修改及姿态变换，默认共同使用**实际查看过的图像与已阅读的形态/解剖描述**，适用于彩色、黑白线稿和通用示意。图像约束可见轮廓、比例、姿态与遮挡，描述约束器官身份、数量、着生、连接和诊断特征；具体执行见 [图像与描述共同约束生物绘图](references/morphology-evidence.md#图像与描述共同约束生物绘图)。优先复用条件相符的已有依据，缺项调用 [物种影像参考](references/species-image-reference.md) 并补查相关描述。通用示意也须选取相容的类群依据；不以“未指定物种”省略结构核对，也不拼接互不相容的性状。

构形前抓住本题少量不可变要求：关键对象/身份、数量/状态、空间/边界、连接/方向，以及允许的简化。每项依据来自用户明确要求、参考可见信息或必要的权威资料；未知的型号、物种或机制先核实。说明、图像与资料冲突时指出具体差异；影响结论且无法消解时询问。

依用途确定保真目标：形态展示保留识别特征与相关比例；机制示意允许非等比例布局，仍须保留实体和机制关系；尺寸、比例尺与定量位置必须有标定或数据依据。普通任务将这些要点融入现有说明/代码即可，不强制另写关系图、JSON 或长报告。

对照依据检查实际成稿中的对象和关系，再检查其视觉实现；发现内容错误先修正。输出中的每个数字、箭头和颜色编码都有明确用途；颜色承担科学含义时配合标签或图例。

涉及具体物种、菌株、组织、分子结构、设备型号或实地剖面时，先核对已有资料的适用性，缺少支持时在线核实影响本图的形态与结构，再构形。生物核对阶段与个体差异，仪器核对型号与配置，分子按层级核对化学结构或三维结构编号与装配状态，场地核对地点与实测记录。通用示意保留其概括层级，单纯改色/移动且不涉及结构判断时无需重新检索。来源选择与特征落图见 [对象特征与结构核实](references/morphology-evidence.md)。形态或空间邻近只支持对应的形态与位置判断；因果、调控和物质输运关系须有任务说明或机制证据。

## 交付约定

- 用户要求展示运输、装配、运动或机制步骤时，按 [科学过程动画](references/scientific-animation.md) 将已确认的科学关系写成部件时间线，输出视频/GIF；过程时间有数据依据时按数据表达。
- 用户要求参数化生成或重复更新论文组图时，分别使用 [参数化批量生成](references/variation-and-learning.md#参数化批量生成) 和 [科研组图](references/figure-composition.md)，交付可复用参数/布局及生成结果。
- 用户说“给我生成回放”“展示从零绘制过程”时，按 [绘制回放](references/drawing-replay.md) 从当前 SVG 生成离散绘制步骤，默认交付 MP4；指定 GIF 或离线 HTML Demo 时交对应格式。步骤根据成稿结构重建，实际历史录屏需有对应记录。
- 用户说“帮我上传 ScanSci”“把这张图分享到素材库”时，按 [上传到 ScanSci](references/scansci-upload.md) 选择本轮明确的成稿、补齐投稿信息并提交。复用已确认的署名、许可和有效授权；首次需要登录时提供官方授权入口。以服务端返回的素材 ID 和状态说明结果。上传流程只在用户提出提交请求时启用。
- 用户要求图片/SVG 转为可编辑 PPT/PPTX 时，按 [可编辑 PPTX 交付](references/pptx-delivery.md) 复用现有原生形状导出工具。单图默认一页，保持原有内容和宽高比；验证实际 PPT 中的文字与部件编辑，交付 PPTX 和实际渲染预览。
- 普通科研绘图默认透明背景 SVG 与 PNG 预览，指定格式按当前请求交付；需要文字时使用可改的 `<text>`，保留可编辑的上下标与特殊字符。参考图含字时，先核对文字内容和对应对象，按需记录位置、方向及层叠；疑字不猜，字体无法识别时用合适替代并说明差异。复杂文字重建读 [文字与部件编辑](references/editable-workflow.md)。
- 整个对象有具名组；内部按用户会移动的部件分组。窗的玻璃、边框、高光同组；叶片及其叶脉、叶柄按联动需求同组。颜色与明暗面跟随所属部件，完整轮廓可以含多条路径。
- 同套素材沿用已确定的配色、描边、光照和细节密度。未指定时自选清晰自然的科研示意风，无需为普通单件反复询问。
- 数量、连接、姿态和科学含义服从描述。陌生物种、型号、分子或机制先核实关键特征；颜色含义、真实部件数与结构特征依对应资料核对。
- 默认静态科研 SVG 使用 viewBox、唯一 ID、原生图形与文字，保持自包含；透明镂空用真实扣空。照片、交互或数据图像面板按已确定的用途保留对应内容，结构检查采用匹配该交付的规则。
- 按已知最终版面尺寸看一次实际预览，确认标签、上下标、关键细线和间隙可辨；未指定尺寸时记录本次检查尺寸。用户指定期刊后，核实并应用对应的字体、线宽与版面要求。

只有用户要求目标编辑器或格式时才做相应交付，沿用可用的导入/导出能力；在副本中验证关键部件选择、文字修改和保存后重开。未在目标应用验证时仅报告 SVG 检查结果。具体检查见 [编辑器交付](references/editable-workflow.md#目标编辑器交付)。

## 制作与修改

用模型已有画法直接构造；重复几何可用短循环，现有可靠部件可复用。路径数量随对象和用途确定，观察记录融入构形；具体困难需要时再增加辅助工具或记录。

### 通用构形约束

- **关系先于修补**：根据描述、参考及必要的领域证据，区分连接、包含、接触、遮挡、相邻和分离；示意连线符合其表达的关系。对象归属依结构与含义确定，保留有意义的空隙及未定关系。
- **几何服从关系**：已确认的接合在构形时共用接口位置；仅对预期平滑处约束切向和宽度过渡，保留真实棱角、关节及开口。包含关系检查内外边界，遮挡关系检查前后顺序。比例、数量和形态依当前对象确定，不套用跨类别固定数值。
- **三种组织分开判断**：实体/科学归属说明“是什么的一部分”，绘制顺序说明“谁遮住谁”，编辑单元说明“用户要一起操作什么”。按编辑意图映射 SVG 组，处理叠放及共享结构，并分别核对科学归属和实际联动。
- **先主形，后细节**：先看整体比例、关键轮廓、关系与识别特征，再补纹理。此判断可融入直接构形，无需额外输出骨架图、关系表或专用引擎；只有具体失误才增加局部参考或几何辅助。
- **修正原因，允许重构**：错位可以移动，错误轮廓可以重画，错误关系可以拆开重组；新增连接需要证据。保护与缺陷无关的正确区域，错误路径不作为必须保留的资产。超出已授权范围的修正先确认。

交付前对照参考与实际渲染，核对科学/语义关系、视觉形态和编辑行为。逐项修复确认的缺陷并复查受影响部分，尤其检查脏斑、残影、接缝和断线。简化时减少非必要细节，保留关键结构；证据不足的部位记录具体未确认项。

局部修正先确定目标部件、需要联动的成员和应保留的关系；移动部件时依据含义决定标签、连接端点是否跟随，共享样式或复用实例的单件修改应隔离影响。保留稳定 ID 和原稿，分别确认目标改善与无关区域保护；无改善或退化就不替换。涉及联动、共享引用或文字重排时读 [文字与部件编辑](references/editable-workflow.md)；需要示范才读 [局部修复案例](references/repair-cases.md)。现有成员与范围检查器按需使用，实际渲染和操作决定编辑是否成功。

绘图默认交付 SVG 与实际预览，转换和修复交付用户要求的目标文件；简述结果、必要的简化/补绘、来源及实际检查。未确认项具体到受影响的内容。报告耗时时采用实际记录，以完整制作或修改时间为主，纯导出时间单列。

## 按对象选择类别

用户要画的生物缺少适用图像依据时，按 [物种影像参考](references/species-image-reference.md) 调用 `species_reference.py`，连接 iNaturalist 或 GBIF 查少量照片及分类记录。已有素材也须核对其证据是否覆盖本图的阶段、姿态和部位；核对名称并查看实际图片，结合形态/解剖描述补齐依据后绘制。保留参考来源，网站入库随用户的上传请求处理。

分类入口覆盖 **16 个主题领域、149 个子类**，见 [完整分类索引](references/taxonomy.md)。每个子类提供典型对象、构形与编辑部件、核对重点；整图组合相关类别，按需读取对应条目。
