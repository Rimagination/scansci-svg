# 变体绘制与增量学习

## 成套变体

用户要求“同一对象多版本”“生长阶段”“对照与处理”“不同视角”或“成套素材”时，先沿用描述确定版本清单、共同特征和变化维度。简单任务将这些信息写在构形代码或简短说明中即可。

| 变化维度 | 应保留 | 需要重新确定 |
| --- | --- | --- |
| 配色、标签语言、展示重点 | 几何、部件身份、科学含义 | 调色映射、文本排版、强调色图例 |
| 姿态、视角、展开与剖面 | 对象身份、结构归属、真实数量 | 遮挡、投影、连接位置与暴露结构 |
| 生长阶段、健康状态、实验处理 | 物种/型号和可对应部件 | 阶段或条件特有的数量、形态与关系，依据匹配资料或用户数据 |

为本套确定一个基准稿。保留统一配色语义、描边、光照、标签和细节密度；各版本从基准或明确的阶段结构生成。姿态和阶段变化按结构重新构形，物种成长涉及器官出现、分枝和比例变化时分别落实。用户点名哪个版本就先完成哪个，通常从信息最充分的一版开始。

同一部件沿用稳定身份，例如各独立文件中的 `roots`、`stem`、`leaves`。新增部件采用新 ID，消失或不可见部件依据该阶段和视角处理；组图时为版本加实例前缀。保留每个版本的标题与阶段/条件说明，变化范围由本次请求决定。

比较实际大小时采用有依据的统一比例；展示形态时可保持统一画布和对齐基准，注明是否归一化。标注同一部件时保持命名一致，位置随姿态调整。版本修订只传播本套明确共享的修正，如共用错字或错误结构，保护各版本特有内容。

只修改颜色或标签时复用已有科学依据。阶段、病理、处理效应或新视角暴露的结构缺少依据时，按 [对象特征核实](morphology-evidence.md) 补查受影响特征；用来源支持变化，不从文件名推断形态。

### 参数化批量生成

优先解决同一部件在整套图中的一致修改。共用修改明确到部件 ID、属性或标签；各版的阶段特征、强调样式和独立注释继续保留。逐版核对目标是否有相同语义和兼容结构，目标已单独改过或阶段结构不同的版本分别处理。单纯拉长或换色可用于检查生成工具，应用价值需用真实编辑任务证明。

对相同 ID 的简单属性/标签修改，复用 `edit_svg.py`，将一份已确认修改应用到指定各版，再用原布局重建组图。分别验证共同修改到位和非目标部分保持不变；不把一次属性变更的检查结论扩展成所有形态修改都能自动传播。

当同一结构需要按明确参数重复生成时，复用 `scripts/variants_svg.py`。在 SVG 属性或文字中写 `{{length}}` 等占位符，保留固定部件 ID；关联部件共用同一参数，例如腔体宽度和出口组的平移量。参数替换发生在 XML 对象上，文本会正确转义。

```json
{
  "template":"chamber-template.svg",
  "parameters":{
    "length":{"type":"number","min":140,"max":330},
    "label":{"type":"choice","values":["Compact","Extended"]}
  },
  "variants":[
    {"name":"compact","values":{"length":160,"label":"Compact"}},
    {"name":"extended","values":{"length":320,"label":"Extended"}}
  ]
}
```

```text
python <skill目录>/scripts/variants_svg.py recipe.json new-variants-directory
```

每版提供全部参数，数值有有限范围，文字/颜色有明确选项。脚本生成各版 SVG 和参数清单，保护源稿并检查结构。模板负责表达关联位置；派生参数由构形代码计算后显式提供。数量、连接拓扑或生长形态变化需要对应的构形逻辑，按实际任务写最小生成代码。检查极值和代表版本的接合、边界、标注与识别特征；结构检查之外查看整套实际预览。

### 一套图怎样交付

逐版核对身份、变化是否到位、连接与数量，再在同一张预览中比较一致性。纯视觉变体比较几何与编辑范围；结构变体同时检查新增、移除及重接的部件。每版交付独立 SVG，整套提供一张总览预览；用户要求整套组图时按 [科研组图](figure-composition.md) 合并。数量较多时可加 ZIP，避免重复导出每版预览或自动生成所有变化维度的组合。

可直接处理的请求示例：

- “同一株水稻，生成自然配色、根系强调、穗部强调三版，姿态保持一致。”
- “生成水稻苗期、分蘖期、抽穗期、成熟期全株图，根茎叶穗分别可编辑；按阶段资料确定形态。”
- “把这个装置画成正视、侧视和工作状态三版，接口与管路保持正确。”

## 从描述到约束

用一句内部草图计划明确对象层级、关键部件、连接位置与可变参数。普通素材无需给用户展示表单，也无需为每次绘图建立 JSON 框架。

“幼苗，3 对对生叶”需要一个整株组、连续茎、三个不同高度的叶位（每位左右两片叶）、叶柄与茎接合、根从茎基部延伸。叶位沿当前幼苗的茎分布。数量、着生位置与连接关系优先于高光纹理。

| 应保持的约束 | 可变参数 | 常见误套 |
| --- | --- | --- |
| 叶/枝与茎的着生关系 | 长宽、弯曲、姿态、疏密 | 所有叶片都从地面发出 |
| 附肢连接、用户指定数量 | 角度、遮挡、局部明暗 | 某种动物的鳍型或足数套到整类 |
| 立面投影与接缝 | 窗行列、屋顶、朝向 | 三维车轮都强行落同一屏幕水平线 |
| 功能端、线缆/管路接口 | 外壳形、配色、摆放 | 外壳相似，探头却不接测量对象 |
| 流动的源、汇、方向与图例 | 曲率、线宽、布局 | 样本颜色/纹理擅自获得反应意义 |

通用对象可直接示意绘制；指定物种、病毒结构、分子结构或真实型号，先核对影响辨识的特征。影响辨识的缺项在构形前核实，其他未定部位按已有证据表达。

## 细节与编辑性

- 路径数、色数、支数服从用途；数值建议按当前对象和用途调整。
- 单对象保留整体组；叶、鳍、轮、传感器按修改需求分组。连续轮廓可用复合路径，无需把每段曲线独立成对象。
- 透明背景的镂空使用复合路径的 `fill-rule="evenodd"` 或其他真正的矢量扣空。白色覆盖会产生白块，在有色背景上仍可见。
- 普通细线明确 `fill="none"` 并设置 stroke。渐细叶、根或缆线用闭合轮廓，或经目标编辑器验证的描边方案；填色的渐细形体保持轮廓闭合。
- 区分总数与可见数。总数保持用户要求，可见数随遮挡确定。

## 最小变体验证

用不同构造暴露缺口：稻→沿茎着生叶的幼苗；侧视车→三分之四视角；白底图标→透明镂空；单向迁移→双向交换。新家族采用结构不同的任务验证。

检查描述约束（数量、接合、朝向）、SVG 自包含和分组，以及正常尺寸/约 96 px 的实际渲染。只对改动相关部件复检，不每轮重跑全库。科学内容与视觉形态通过对照参考和实际渲染核对。
