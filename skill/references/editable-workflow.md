# 文字与部件编辑

用于含字参考图重建、转绘伪影清理、部件联动、共享实例修改，以及指定编辑器交付。简单无字对象直接绘制；只读当前任务需要的段落。

## 参考图忠实重建

适用于整张参考图转为可编辑 SVG 或指定区域还原；以参考图的视觉表达为基准，沿用下方文字、洁净度和编辑规则。

- **画布与布局**：读取原始文件尺寸，以整图或指定裁切区域的宽高比建立 viewBox。保留主要对象的相对位置、尺寸、间距、方向、叠放与配色；重新排版、美化或替换图标按用户要求执行。带有科学含义的背景区域也作为对象保留。
- **内容对应**：沿原图区域逐项核对主体、图标、文字、图例及箭头；跨区域连接单独核对起点、终点、方向和所表达的关系。对应记录融入已有制作说明即可。主要内容的数量与含义保持，压缩色斑和抗锯齿碎片按洁净度规则处理。
- **编辑单位**：轮廓、色面、细节按所属对象组织，主要对象可独立选择；用户会一起移动的成员归入具名组，内部保留可改部件。文字按下节恢复为原生文本，箭头按实际端点和方向构造。
- **差异处理**：局部不清楚时先放大原图，利用任务资料核实；仍无法确定的文字或结构标明具体位置与缺项，继续明确部分。原图与科学依据冲突时说明冲突，按已授权的纠错范围处理科学含义的修改。
- **对照验收**：把原图和 SVG 实际渲染对齐到相同画幅，先看布局与主要色块，再查文字、对象遗漏、连接方向和接合；最后按交付尺寸检查细线与标签可读性。交付说明列出实质差异、字体替代和未确认项。目标编辑器兼容性沿用 [实际操作验证](#目标编辑器交付) 的结果。

## 保真与细节选择

先判断参考承担的角色和用户的编辑用途，再决定每个区域的表示方法。重建与临摹可以用于同一张图的不同部位。

| 任务侧重 | 优先落实 | 局部处理 |
| --- | --- | --- |
| 科研示意图重建、图片转可编辑图 | 对象身份、文字、连接、数量、构图与可改部件 | 规则对象直接构造，复杂轮廓依参考描摹；底色合并为所属对象的连续色面 |
| 精细临摹、插画复现、保留质感 | 构图比例、轮廓转折、线宽变化、色彩层次、材质与叠放 | 为有意义的羽毛、叶脉、锯齿、颗粒与明暗投入足够路径，保留局部不对称和特征 |
| 参考风格或重新设计 | 用户指定的对象和科学内容，以及参考的画法 | 允许的布局与姿态变化依任务决定，参考图中的内容不自动进入新图 |

“精确还原”优先保留参考内容和视觉特征。连续平滑区域中的压缩色块、抗锯齿残边、描摹重叠片及去字残影按成因清理；真实斑纹、细小刻度、数据点、羽枝或材质颗粒依据其功能和原图证据保留。判断结合原始分辨率、局部放大和目标展示尺寸，小面积、多颜色或路径多都不单独构成删除理由。

细节密度按区域分配：主体识别特征、重点局部、文字和科学关系优先；其他区域保持原图的视觉密度。用完整轮廓、局部色面或矢量纹理表达相同效果；结构有组织即可容纳较多路径。对照原图检查代表性的精细区和平滑区，同时确认“没有丢掉重要细节”和“没有增添脏斑碎片”。

用户明确指定“参考图作为唯一视觉依据”时，从它确定外观，不混入其他图的形态。仍按当前授权处理科学疑点；需要改变原图内容的纠错先说明。模糊细节先检查原文件，证据不足时保留其可辨层级；若保留/概括会明显改变用户目标，再询问。

### 自包含 HTML 与绘制 Demo

图件由原生 SVG 图形和文字元素构成，HTML/CSS 承载布局与交互。用户要求单文件离线 Demo 时，将 SVG、样式和播放器逻辑放在一个 HTML 中，使用系统字体，不引用外部框架、字体或在线资源；原图、Base64 位图、Canvas 截图均不作为 SVG 成稿内容。

用户要求“只输出代码”时按该交付要求返回完整代码；它只约束相应任务的回答格式。通常交付可打开的文件和实际预览。要求绘画回放时按 [绘制回放](drawing-replay.md) 单独编排步骤；参考的颜色渐变、原始透明度和阴影可保留，离散回放的步骤之间直接切换。

## 描摹与部件整理

按任务准备可选依赖：Python、Pillow 与 VTracer。本入口已验证 `vtracer==0.6.15` 的 `convert_image_to_svg_py` API；安装到当前任务使用的 Python 环境即可。其他绘图和编辑脚本沿用各自依赖。

```text
python -m pip install Pillow vtracer==0.6.15
python <skill目录>/scripts/trace_svg.py input.png output.svg
python <skill目录>/scripts/trace_svg.py isolated-part.png part.svg --group-id wing --filter-speckle 1
```

入口保留输入的画幅，应用照片 EXIF 方向后转换，生成 viewBox、一个整图/已分离区域组及可寻址的路径 ID。已有目标文件会保留，请另选输出文件。标准输出 JSON 记录依赖版本、实际参数、纯转换与本次调用总耗时；预览复用宿主已有浏览器或 SVG 渲染器。路径按图像色块生成，部件语义与文字恢复由后续操作完成。

常用参数：`--colormode color|binary`、`--mode spline|polygon|none`、`--filter-speckle 0..128`、`--color-precision 1..8`、`--layer-difference 0..255`。binary 按白纸黑线处理，透明输入先合成白底，输出中白色区域留空。先用默认值看结果，再根据已观察的缺陷调整相关参数；碎点过滤可能一并去除细小真实结构，需对照检查。平滑明暗出现色带时，可重建对应连续渐变；规则对象与文字直接构形。

1. **明确修改范围**：从图意和参考确定完整部件及随动成员；按需分开花瓣与花心、实体与标签、对象与连接。整图组仅代表全部描摹内容。
2. **处理跨区路径**：框选与包围盒用于定位。路径跨越多个部件时，拆分路径，或先依据可见边界将参考部件分离为透明图再描摹。保留原画幅或记录偏移，合成时沿用坐标与层次；分离范围同时检查细线、附属结构和抗锯齿边缘。
3. **整理遮挡与底色**：移动前检查部件下方是否留有旧轮廓、空洞或缺失底色。显露区域依据参考可见信息与任务资料补绘，标明实质补绘；科学内容不明确且影响结果时追问。核对新接合和叠放。
4. **执行相关编辑**：在副本中实际换色、移动或改字，检查目标成员是否完整变化、应保留的内容是否保持，以及残边、接缝和连接。源码范围检查与实际预览一起决定是否完成；指定编辑器时在对应应用验证。

保留已验收的描摹稿、部件分离结果与文字记录，后续修改复用 `edit_svg.py` 等现有工具。预览集中核对当前图件，返修后复查受影响区域。交付范围覆盖整图时，逐一完成其余部件与文字的整理；单个目标编辑通过仅说明该操作的结果。

## 参考文字重建

- 逐一恢复参考范围内可辨认的文字，并与它标识的对象或关系对应；保留数值、单位、希腊字母、上下标、换行和箭头方向等科学含义。记录可沿用任务说明或代码变量，只有复杂排版或多轮恢复才另存文字清单。
- 忠实复现时保留参考位置、旋转、对齐和层叠；用户允许重新布局时随对象调整。参考没有字体元数据时，选择视觉接近的替代字体，并记录字体替代。
- 疑字先看原图局部或已有说明；影响科学含义仍无法确认时询问。不得借转绘改写数值、单位或将估计字形当原文。清晰内容继续制作。
- 直接重绘无需先去字。确需去字再矢量化时，先保留原图及文字记录；处理后对照非文字结构，特别看文字附近的箭尾、刻度、细线和边界，修复处理引入的变化后再接受结果。
- 用 `<text>`/`<tspan>` 恢复普通文字，必要时明确上下标的字号和基线偏移；几何描摹得到的字形路径应由可编辑文字替换，避免重复字。只有用户要求转曲时才交转曲副本并保留可编辑源稿。
- 按最终版面看一次实际渲染，核对文字内容、缺字、上下标、遮挡、错绑对象和越界。XML 中存在 `<text>` 只能证明有文字节点。

## 转绘洁净度

- **先理解整图，再选择画法**：先识别主要区域中的对象，以及跨区域的连接、包含、流向和标注关系；对待绘对象确定主体、必要部件、前后叠放和编辑归属，再构造路径。例如建筑由墙面、屋顶、窗户组成，窗户内部颜色变化不改变其归属。对象判断融入现有构形与分组即可，无需额外清单、JSON 或等待用户批准拆解。
- **按对象选择表示**：规则形体使用基本几何，重复部件复用几何，连续轮廓用可控曲线，明确的体积明暗用连续填充或渐变。精细临摹时按参考保留复杂轮廓和局部纹理；示意重建时按对象组织形体。每一区域选择能保留目标特征且便于修改的表示，路径数量随细节需要确定。无法确认的结构保留其可辨层级，不从压缩色斑或抗锯齿像素推断新部件。
- **颜色服从部件**：每条主要轮廓或色面应能说明属于哪个对象、表达何种边界、材质、阴影或纹理。按完整对象组织这些色面，并核对部件成员及实际编辑行为。
- **文字与底图一起清理**：恢复可编辑文字时，清除对应的旧字轮廓、抗锯齿残边及去字产生的斑点；底色应与所属形状连续。平滑区域出现方块、色带或脏边时，直接替换该区域的底色几何并移除失效碎片，重接必要的箭头和边界，避免用不同色矩形盖住旧字后留下补丁。
- **按含义保护细节**：对照参考区分伪影与真实纹理、表面颗粒、分界虚线、箭头、刻度及数据点。按目标部件清理，保留有意义的数量、位置与方向；清理范围依据上述含义逐对象确定。
- **目检要作出判断**：整体预览确认构图与关系，再以原始像素尺寸或适当放大对照关键平滑区域、恢复文字附近和细线交界。每处可见异常都要判断属于参考内容、允许的简化或制作缺陷；确认的残影、接缝、光晕和断线先修正，再复查结果。
- **失败时切换表示方法**：简单对象出现无意义色面或碎片，立即停止对它调色区参数，重建完整对象并移除失效路径。若当前任务中的多个对象反复出现同类问题，检查它们共用的生成方法，修正该方法并处理受影响的对象。按已授权范围修复，保护正确对象；局部结果清晰且关系完整即可结束，不增加全图试参循环、固定路径阈值或新审查流程。

## 按部件执行修改

先从当前 SVG 与任务确定三件事：目标部件、随它变化的成员、保持不变的对象和关系。沿用原有分组；分组妨碍正确编辑时才局部重构。部件归属依对象结构与编辑意图确定。

| 修改意图 | 联动与保护要求 |
| --- | --- |
| 移动或旋转部件 | 核对轮廓、内部细节及附属标注；测量轴或公共图例按其用途独立保留。 |
| 改一个重复实例的颜色/形状 | 检查 `use`、共享定义与样式；优先实例属性覆盖，必要时复制最小依赖并使用唯一 ID，保护其余实例。 |
| 改标签 | 修改文字及其必要排版；保留所指对象、单位和未要求变更的内容，避免变长后遮住箭头或边界。 |
| 移动带连接的对象 | 根据任务保持连接含义、端点归属与方向；仅更新必要端点/路径，仍然交叉但不相连的对象保持分离。 |

依赖对象的必要改动属于该编辑的范围，例如移动节点后接回它的连接线；在修改前界定范围，不为消除检查报错而扩大范围。请求“其余全部不变”与必要联动冲突时，先指出冲突并确认取舍。

在副本中执行当前要求的实际操作，检查目标是否达到要求、联动成员是否完整、无关区域是否保持、层叠是否合理。新素材没有指定编辑动作时，仅在联动有疑问处做一次代表性操作并撤销或丢弃副本，不为每个小对象增加测试流程。

需要工具证据时复用已有脚本；以下示意 ID 须替换为当前文件的真实 ID：

已有 SVG 的改色、位移和简单文字修改可用 `scripts/edit_svg.py` 按 ID 执行，保持未修改路径与原文件。修改 JSON 是数组，例如：

```json
[
  {"id": "panel-b--leaf-2-left", "attributes": {"transform": "rotate(12 120 176)"}},
  {"id": "b-title", "text": "B  Revised"}
]
```

```text
python <skill目录>/scripts/edit_svg.py before.svg edits.json after.svg
```

同一目标的修改放在一项中；`attributes` 替换指定节点上的属性，原有变换需要组合后填写，子节点已有颜色按其真实 ID 分别修改。同节点的内联样式覆盖了目标属性时，脚本给出具体冲突，转到源文件修改对应声明。文字写到没有子元素的 `text` 或 `tspan`，保留上下标结构。脚本复用范围检查，输出实际变更的 ID；存在共享引用影响或需要改轮廓时，直接编辑源文件并检查相应依赖。成功后看一次实际渲染，确认颜色、位置和文字达到要求。

```powershell
python skill/scripts/check_edit_units.py figure.svg --unit window=frame,glass
python skill/scripts/check_edit_scope.py before.svg after.svg --allow window
```

以上命令从维护项目根目录运行；已安装 skill 按其目录解析脚本路径。成员检查验证指定成员在组内，成员完整性与联动通过实际操作核对；范围检查比较源码，遇到共享引用、CSS 或合法重构时核对依赖与实际渲染。两个检查均已包含 SVG 结构检查，运行其中之一即可覆盖该项。

## 目标编辑器交付

仅在用户指定 Illustrator、Inkscape、PowerPoint 等目标应用时执行。用现有可靠工具处理，保留原始 SVG；依据目标应用实际支持情况生成兼容副本，将兼容性处理记录到对应应用。

在独立副本或测试文档中导入，试选一个任务相关部件并做指定操作；有文字时实际改一处，随后保存并重开，核对文字、部件联动、层叠和透明效果。检查用改动应撤销，交付文件保持用户要求。若用户授权写入已有文档，保留其中已有内容并另存结果，避免覆盖原件。

只完成导出时记“已导出、目标应用编辑未验证”；完成实际操作才报告所测应用与行为。可编辑 SVG、目标应用原生对象和科学内容正确分别陈述。
