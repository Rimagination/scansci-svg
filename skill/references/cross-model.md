# 跨模型执行卡：按失误启用辅助

**优先推荐 GPT-6 Astra。** 其他模型的成图质量可能大打折扣，使用时重点查看科学结构、自然轮廓及编辑部件的衔接。推荐配置与当前成稿的实际质量分别记录。

适用：换宿主、看图能力不确定、当前绘图失稳。熟悉且已达标的任务直接执行，不增加每步审批、强制多阶段产物或预先能力考试。

## 输入能力与绘图能力分开

- 确认实际图像已通过附件或看图工具送入模型；通过实际图像观察确认输入已可见。可用当前图独有的姿态、色区与遮挡核对，不必单独写报告。
- 实际无法看图时，停止照片忠实转绘，请用户补图或允许按描述绘制；将该情况记录为工具缺项。无法渲染/看成稿时标“视觉未验”。
- 测试时记录实际宿主、模型 ID、推理设置；无法取得的值写未确认。
- 照片、文字和生成图采用入口页的同一科学表达约定。用户要求独立生成参考时才调用可用图像工具；工具缺失时说明当前缺项，保持用户选定的输入路线。生成参考的科学内容仍须依据任务/独立资料核对；鸟类另有 [专项规则](bird-photo.md)。

## 路线选择

路线针对当前任务与缺陷，可组合局部辅助；不建立“某模型永远走某档”的映射。用户指定做法与预算优先。

| 当前证据 | 选择 | 具体动作与退出条件 |
| --- | --- | --- |
| 无失败证据，或同类任务已稳定完成 | 直接构形 | 按视觉理解写曲线、色区和必要细节；正常渲染自检即可，不先测全套题 |
| 对象身份、空间或机制关系有冲突 | 证据核对 | 回查描述、图像或领域资料，确认关键要求后修正；证据不足时只询问影响结果的缺项 |
| 关键部件比例、位置或投影失真 | 局部几何辅助 | 只记录问题部位的少量锚点/比例，修轮廓或接合；渲染确认后继续直接补细节 |
| 轮廓已对，纹理/边缘仍机械或过简 | 局部画法辅助 | 查看一个相关范例的对应区域，学习方向、疏密、层叠与边缘；保留正确几何，修改该区后退出 |
| 拖动部件后留下附属细节 | 编辑结构辅助 | 修所属组的嵌套和必要局部引用，验证部件联动与层叠；不重画已正确轮廓 |
| 一次针对性修正后，关键结构仍明显错误 | 有界收缩 | 保存当前稿和具体缺陷；有合适且许可明确的部件时提出局部复用，否则说明需其他模型/人工辅助。涉及改模型、付费、扩时或降目标，先取得用户方向 |

完成一次针对性修正后评估效果，按用户方向与剩余预算继续。模型切换按用户要求执行，质量状态依据实际成稿记录。

## 辅助要对症

- **喙过长**：先分清嘴角、外露喙基、额头连接和喙尖，再观察与眼心的关系；只修必要部件。自估坐标可能延续视觉错误，不因有坐标表就提升置信。看不清时仅放大该处；修后必须看外露长度与连接是否实际改善。增加羽毛或路径数不解决这项误差。
- **羽斑块状**：保留已正确的轮廓，按头、背翼、胸腹区分斑纹方向与尺度；避免全身等距锯齿、同形心形点或随机短线。少量非重复的羽缘变化即可，不为当前图开发纹理系统。
- **坐标混乱**：选原图像素或归一化坐标之一，裁剪时记录原点；渲染视口保持 viewBox 比例，不拉伸预览来掩盖失真。
- **分组错误**：头部羽斑随 head、羽纹随 wing/body；两只可见且需分别调整的足独立分组。羽饰归入对应的头、翼或身体组。
- **参考错用**：样例只教曲线与组织方式；新图的姿态、发育阶段、可见斑纹决定几何与配色。看不清的点标遮挡；发育阶段依当前照片和对应资料确定。足式与展示补画见鸟类规则。

## 能力记录的边界

记录“模型＋版本/宿主＋设置＋任务类型＋实际结果”，允许同一模型擅长规则设施却不擅长鸟类。已有相关记录只提供起点；模型版本、宿主工具或任务类型改变后，置信度降低，使用当前首稿校准。

质量由原图或任务要求与实际渲染对比判断，记录具体部位的改善与剩余缺陷。到用户预算即保留已完成文件并说明缺项，统计完整执行时间。

修复参考按 [案例索引](repair-cases.md) 的缺陷标签检索，一次只看相关局部；失败案例用于定位缺陷，候选稿完成验证后再作为画法参考。修改前后没有可见改善，保留原稿并说明，避免反复叠加补丁。

只有用户要求评测或确需维护路线证据时，执行 [轻量回归评测](evaluation.md)。通过实际对照记录辅助方式对画质、耗时和修正量的影响。
